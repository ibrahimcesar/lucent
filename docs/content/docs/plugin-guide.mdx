## Overview

Lucent's plugin system allows you to:

- **Extend Language Support** - Add support for new programming languages
- **Improve Accuracy** - Use AST-based analysis (e.g., tree-sitter) instead of regex
- **Custom Metrics** - Implement domain-specific code quality metrics
- **Output Formats** - Add custom report formats

### Architecture

```
┌─────────────────┐
│  Lucent Core    │
```

## Plugin API

### Core Trait

```rust
use lucent::plugin::{MetricProvider, PluginMetadata, PluginCapability};
use lucent::metrics::FileMetrics;
use anyhow::Result;
use std::path::Path;

pub trait MetricProvider: Send + Sync {
    /// Get plugin metadata
    fn metadata(&self) -> PluginMetadata;

    /// Get supported languages
    fn supported_languages(&self) -> Vec<&str>;

    /// Analyze source code
    fn analyze(&self, path: &Path, source: &str, language: &str)
        -> Result<Option<FileMetrics>>;

    /// Plugin priority (higher = preferred)
    fn priority(&self) -> u32 { 50 }
}
```

### Plugin Metadata

```rust
pub struct PluginMetadata {
    pub name: String,
    pub version: String,
    pub author: String,
    pub description: String,
    pub api_version: String,
    pub capabilities: Vec<PluginCapability>,
}
```

### Plugin Capabilities

```rust
pub enum PluginCapability {
    /// Provides metrics for specific languages
    MetricProvider(Vec<String>),

    /// Provides custom output formatting
    OutputFormatter(String),

    /// Provides additional quality checks
    QualityChecker,
}
```

## Creating a Plugin

### 1. Create a New Crate

```bash
cargo new lucent-plugin-myanalyzer --lib
cd lucent-plugin-myanalyzer
```

### 2. Add Dependencies

```toml
[dependencies]
lucent = "0.1"
anyhow = "1.0"
```

### 3. Implement MetricProvider

```rust
use lucent::plugin::{MetricProvider, PluginMetadata, PluginCapability};
use lucent::metrics::FileMetrics;
use anyhow::Result;
use std::path::Path;

pub struct MyAnalyzer;

impl MetricProvider for MyAnalyzer {
    fn metadata(&self) -> PluginMetadata {
        PluginMetadata {
            name: "my-analyzer".to_string(),
            version: env!("CARGO_PKG_VERSION").to_string(),
            author: "Your Name".to_string(),
            description: "My custom analyzer".to_string(),
            api_version: lucent::plugin::PLUGIN_API_VERSION.to_string(),
            capabilities: vec![
                PluginCapability::MetricProvider(vec![
                    "Rust".to_string(),
                    "Python".to_string(),
                ])
            ],
        }
    }

    fn supported_languages(&self) -> Vec<&str> {
        vec!["Rust", "Python"]
    }

    fn analyze(&self, path: &Path, source: &str, language: &str)
        -> Result<Option<FileMetrics>>
    {
        if !self.supports_language(language) {
            return Ok(None);
        }

        // Your custom analysis logic here
        let metrics = FileMetrics {
            // ... populate metrics ...
            ..Default::default()
        };

        Ok(Some(metrics))
    }

    fn priority(&self) -> u32 {
        // Higher than default (50) to be preferred
        70
    }
}
```

### 4. Register Your Plugin

```rust
use lucent::plugin::PluginRegistry;
use std::sync::Arc;

fn main() {
    let mut registry = PluginRegistry::new();

    let plugin = Arc::new(MyAnalyzer);
    registry.register(plugin).unwrap();

    // Use the plugin
    let provider = registry.find_for_language("Rust").unwrap();
    let metrics = provider.analyze(path, source, "Rust").unwrap();
}
```

## Built-in Plugins

Lucent ships with a built-in regex analyzer:

```rust
use lucent::plugin::RegexAnalyzer;

let analyzer = RegexAnalyzer::new();
let metadata = analyzer.metadata();
// name: "lucent-builtin-regex"
// Supports all 21+ languages
// Priority: 10 (lower than external plugins)
```

This ensures Lucent works out-of-the-box while allowing plugins to override with better analysis.

## Configuration

### Enable Plugins

Add to `.lucent.toml`:

```toml
[plugins]
# List of enabled plugins
enabled = ["tree-sitter", "my-custom-analyzer"]

# Use plugins for analysis (vs built-in regex)
use_for_analysis = true

# Fallback to built-in if plugin fails
fallback_on_error = true
```

### Per-Language Plugin Selection

If multiple plugins support the same language, the one with **highest priority** is used:

```rust
impl MetricProvider for TreeSitterPlugin {
    fn priority(&self) -> u32 { 100 }  // Very high priority
}

impl MetricProvider for RegexAnalyzer {
    fn priority(&self) -> u32 { 10 }   // Low priority (fallback)
}
```

## Example: Tree-sitter Plugin

Here's a complete example of a tree-sitter plugin for Rust:

```rust
use lucent::plugin::{MetricProvider, PluginMetadata, PluginCapability};
use lucent::metrics::FileMetrics;
use anyhow::{Result, Context};
use std::path::Path;
use tree_sitter::{Parser, Language};

extern "C" {
    fn tree_sitter_rust() -> Language;
}

pub struct TreeSitterRustPlugin {
    parser: Parser,
}

impl TreeSitterRustPlugin {
    pub fn new() -> Result<Self> {
        let language = unsafe { tree_sitter_rust() };
        let mut parser = Parser::new();
        parser.set_language(language)
            .context("Failed to load Rust grammar")?;

        Ok(Self { parser })
    }

    fn calculate_complexity(&self, tree: &tree_sitter::Tree) -> usize {
        let mut complexity = 1; // Start at 1

        let query_str = r#"
            (if_expression) @decision
            (match_expression) @decision
            (while_expression) @decision
            (loop_expression) @decision
            (for_expression) @decision
            (binary_expression
                operator: ["&&" "||"] @decision)
        "#;

        let query = tree_sitter::Query::new(language, query_str).unwrap();
        let mut cursor = tree_sitter::QueryCursor::new();

        for _ in cursor.matches(&query, tree.root_node(), source.as_bytes()) {
            complexity += 1;
        }

        complexity
    }
}

impl MetricProvider for TreeSitterRustPlugin {
    fn metadata(&self) -> PluginMetadata {
        PluginMetadata {
            name: "lucent-plugin-treesitter-rust".to_string(),
            version: "0.1.0".to_string(),
            author: "Lucent Team".to_string(),
            description: "Tree-sitter based Rust analyzer".to_string(),
            api_version: lucent::plugin::PLUGIN_API_VERSION.to_string(),
            capabilities: vec![
                PluginCapability::MetricProvider(vec!["Rust".to_string()])
            ],
        }
    }

    fn supported_languages(&self) -> Vec<&str> {
        vec!["Rust"]
    }

    fn analyze(&self, path: &Path, source: &str, language: &str)
        -> Result<Option<FileMetrics>>
    {
        if language != "Rust" {
            return Ok(None);
        }

        let tree = self.parser.parse(source, None)
            .context("Failed to parse Rust source")?;

        let complexity = self.calculate_complexity(&tree);

        let metrics = FileMetrics {
            cyclomatic_complexity: complexity,
            // ... populate other metrics from AST ...
            ..Default::default()
        };

        Ok(Some(metrics))
    }

    fn priority(&self) -> u32 {
        100 // High priority - prefer tree-sitter over regex
    }
}
```

### Using the Tree-sitter Plugin

```rust
use lucent::plugin::PluginRegistry;
use std::sync::Arc;

let mut registry = PluginRegistry::new();

// Register tree-sitter plugin
let ts_plugin = Arc::new(TreeSitterRustPlugin::new()?);
registry.register(ts_plugin)?;

// Register fallback regex plugin
let regex_plugin = Arc::new(lucent::plugin::RegexAnalyzer::new());
registry.register(regex_plugin)?;

// Find best plugin for Rust
let provider = registry.find_for_language("Rust").unwrap();
// Returns tree-sitter plugin (priority 100 > 10)
```

## Testing Plugins

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_plugin_metadata() {
        let plugin = MyAnalyzer;
        let meta = plugin.metadata();

        assert_eq!(meta.name, "my-analyzer");
        assert_eq!(meta.api_version, lucent::plugin::PLUGIN_API_VERSION);
    }

    #[test]
    fn test_supported_languages() {
        let plugin = MyAnalyzer;

        assert!(plugin.supports_language("Rust"));
        assert!(plugin.supports_language("Python"));
        assert!(!plugin.supports_language("JavaScript"));
    }

    #[test]
    fn test_analysis() {
        let plugin = MyAnalyzer;
        let source = "fn main() {}";
        let path = Path::new("test.rs");

        let result = plugin.analyze(path, source, "Rust");

        assert!(result.is_ok());
        assert!(result.unwrap().is_some());
    }
}
```

## Dynamic Plugin Loading

Dynamic plugins are loaded at runtime from shared libraries (`.so` on Linux, `.dylib` on macOS, `.dll` on Windows). This allows plugins to be distributed as binary files without requiring recompilation of Lucent.

### Creating a Dynamic Plugin

#### 1. Create a New Library Crate

```bash
cargo new my-lucent-plugin --lib
cd my-lucent-plugin
```

#### 2. Configure Cargo.toml

```toml
[package]
name = "my-lucent-plugin"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]  # Required for dynamic loading

[dependencies]
lucent = "0.1"
```

#### 3. Implement DynamicPlugin Trait

```rust
use lucent::plugin::{DynamicPlugin, PluginMetadata, PluginCapability, declare_plugin};
use lucent::metrics::FileMetrics;
use std::path::Path;

pub struct MyDynamicAnalyzer;

impl DynamicPlugin for MyDynamicAnalyzer {
    fn metadata(&self) -> PluginMetadata {
        PluginMetadata {
            name: "my-dynamic-analyzer".to_string(),
            version: "0.1.0".to_string(),
            author: "Your Name".to_string(),
            description: "A dynamically loaded analyzer".to_string(),
            api_version: lucent::plugin::DYNAMIC_PLUGIN_API_VERSION.to_string(),
            capabilities: vec![
                PluginCapability::MetricProvider(vec![
                    "Rust".to_string(),
                    "Python".to_string(),
                ])
            ],
        }
    }

    fn supported_languages(&self) -> Vec<String> {
        vec!["Rust".to_string(), "Python".to_string()]
    }

    fn analyze(&self, path: &Path, source: &str, language: &str) -> Option<FileMetrics> {
        if !self.supported_languages().iter().any(|l| l == language) {
            return None;
        }

        // Your custom analysis logic here
        let metrics = FileMetrics {
            // ... populate metrics ...
            ..Default::default()
        };

        Some(metrics)
    }

    fn priority(&self) -> u32 {
        80  // Higher than default (50) to be preferred
    }

    fn on_unload(&self) {
        // Optional cleanup when plugin is unloaded
        println!("MyDynamicAnalyzer unloaded");
    }
}

// IMPORTANT: This macro exports the required C functions for dynamic loading
declare_plugin!(MyDynamicAnalyzer, MyDynamicAnalyzer);
```

#### 4. Build the Plugin

```bash
cargo build --release
```

The compiled plugin will be in:
- **Linux**: `target/release/libmy_lucent_plugin.so`
- **macOS**: `target/release/libmy_lucent_plugin.dylib`
- **Windows**: `target/release/my_lucent_plugin.dll`

### Installing Dynamic Plugins

Copy the compiled library to one of these directories:

```bash
# User plugins (recommended)
~/.lucent/plugins/

# System-wide plugins
/usr/local/lib/lucent/plugins/

# Project-specific plugins
./.lucent/plugins/
```

### Loading Dynamic Plugins

```rust
use lucent::plugin::{DynamicPluginManager, PluginRegistry};
use std::path::Path;
use std::sync::Arc;

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut manager = DynamicPluginManager::new();

    // Load a single plugin
    let plugin = manager.load(Path::new("./plugins/libmy_plugin.dylib"))?;
    println!("Loaded: {}", plugin.metadata().name);

    // Or discover all plugins in a directory
    let discovered = manager.discover_plugins(Path::new("~/.lucent/plugins/"))?;
    println!("Discovered {} plugins", discovered);

    // Use with PluginRegistry
    let mut registry = PluginRegistry::new();

    // Convert loaded plugins to metric providers
    for loaded in manager.loaded_plugins() {
        // The loaded plugin can be used directly
        let metrics = loaded.analyze(Path::new("test.rs"), "fn main() {}", "Rust");
    }

    Ok(())
}
```

### Plugin Discovery Order

When discovering plugins, Lucent searches in this order:

1. `./.lucent/plugins/` - Project-specific plugins
2. `~/.lucent/plugins/` - User plugins
3. `/usr/local/lib/lucent/plugins/` - System plugins

### The declare_plugin! Macro

The `declare_plugin!` macro generates the necessary C-compatible functions for dynamic loading:

```rust
// This macro expands to:
// - _lucent_plugin_api_version() -> returns API version string
// - _lucent_plugin_create() -> creates and returns the plugin instance

declare_plugin!(PluginType, PluginType);
//              ^^^^^^^^^   ^^^^^^^^^
//              The type    Constructor expression
```

### API Version Compatibility

Dynamic plugins must match the Lucent API version. Check compatibility:

```rust
use lucent::plugin::DYNAMIC_PLUGIN_API_VERSION;

// In your plugin
fn metadata(&self) -> PluginMetadata {
    PluginMetadata {
        api_version: DYNAMIC_PLUGIN_API_VERSION.to_string(),
        // ...
    }
}
```

If versions don't match, Lucent will refuse to load the plugin with a clear error message.

### Dynamic Plugin Error Handling

```rust
use lucent::plugin::{DynamicPluginManager, DynamicPluginError};

let mut manager = DynamicPluginManager::new();

match manager.load(Path::new("./plugin.so")) {
    Ok(plugin) => println!("Loaded: {}", plugin.metadata().name),
    Err(DynamicPluginError::LibraryLoadFailed(path, err)) => {
        eprintln!("Failed to load library {}: {}", path.display(), err);
    }
    Err(DynamicPluginError::SymbolNotFound(name)) => {
        eprintln!("Plugin missing required symbol: {}", name);
    }
    Err(DynamicPluginError::ApiVersionMismatch { expected, found }) => {
        eprintln!("API version mismatch: expected {}, found {}", expected, found);
    }
    Err(DynamicPluginError::PluginCreationFailed) => {
        eprintln!("Plugin constructor returned null");
    }
    Err(e) => eprintln!("Error: {}", e),
}
```

### Security Considerations

Dynamic plugins run with the same permissions as Lucent. Only load plugins from trusted sources:

- Verify plugin source and author
- Review plugin code before loading
- Use project-specific plugins (`./.lucent/plugins/`) for untrusted plugins
- Consider sandboxing for production environments

## Best Practices

1. **API Version Compatibility** - Always use `lucent::plugin::PLUGIN_API_VERSION` for static plugins or `DYNAMIC_PLUGIN_API_VERSION` for dynamic plugins
2. **Error Handling** - Return `Ok(None)` for unsupported languages, `Err` for failures
3. **Priority** - Use higher priority (>50) for better analyzers, lower (<50) for fallbacks
4. **Thread Safety** - Implement `Send + Sync` (required by trait)
5. **Performance** - Cache parsers/grammars in struct, don't recreate per-file
6. **Testing** - Test with various code samples and edge cases
7. **Documentation** - Document supported languages and limitations
8. **Dynamic Plugins** - Always use `declare_plugin!` macro for proper FFI exports

## Troubleshooting

**Q: My plugin isn't being used**
A: Check priority - higher priority plugins are preferred

**Q: Plugin fails to load**
A: Verify API version matches: `lucent::plugin::PLUGIN_API_VERSION`

**Q: Thread safety errors**
A: Ensure your plugin implements `Send + Sync`

**Q: Performance issues**
A: Cache expensive initialization (parsers, grammars) in plugin struct
